# CocosCreator 快速開發輕量級遊戲框架
# 項目說明
Node: v18.15.0
本項目基於 cocos creator 3.7.2版本
以Asset Bundle為基礎的大廳+子遊戲示例
提供一個輕量級的遊戲開發框架,讓你的開發更加簡單

# 更新

# cocos creator 升級

引擎修正插件可直接對 3.7.2 版本
項目中示例專案可自行按自己項目進行裁剪

升級步驟

1，升級後使用一次【引擎修正】插件

2，重新構建項目

# 完整專案拉取

進入tools 目錄先執行 npm install 安裝依賴

然後在tools目錄下執行 npm run main

# 關於QuickFramework
- **Q : 為什麼使用單場景？**
    - **保證視圖在切換場景時正常彈出**
    * 如下情況，如多場景情況下，A場景->B場景，A場景上請求網路數據希望在B場景上彈出，當收到網路返回時
    還需要檢查當前是否在B場景中，如果不在則壓入到顯示隊列中，等進入B場景，檢查當前是否有顯示視圖隊列
    如果有顯示的視圖，依次彈出，但如果採用單場景化，無須關心在哪一個場景，收到網路回複直接彈出。
    - **保護界麵狀態**
    * 還是在多場景下，在切換場景時，必定會先把場景上所有視圖關閉，清除數據，但若有需要在A場景下顯示的
    界麵也希望在B場景下顯示，此時場景的過渡，會先關閉界麵，進入B場景時顯示，但如果場景上有ListView類
    似的控件，也希望在切換場景時，顯示之前玩家操作顯示的位置，那麼必定會花費額外的工作去保存玩家在A場景
    上操作界麵的相關信息，再進入B場景時，恢複玩家對界麵操作的所有狀態，但如果隻是單場景，可以類比一個
    場景的切換動作，直接隱藏掉界麵，進入B場景，直接顯示，無須保存界麵的狀態。

- **Q : 項目為什麼不推薦使用在預置體中直接掛載腳本？**
    - **方便重構**
    * 如下情況，當你發現目錄結構不合理，或者文件名取名有誤時，但此時已經在預置上掛載了過多的組件，還有
    些項目的子遊戲是在不同的svn版本管理下，在開發時，並不會放入全量的代碼進入開發，如果如果此時改名或
    移動目錄，可能會造成文件的uuid發生變化，Creator上隻會顯示該腳本為Misson狀態，並不會顯示之前掛載
    的是哪一個腳本，若項目足夠大，一個腳本的uuid變化，可能會造成大量預置體重新設定掛載腳本，提高了
    維護的成本
- **Q : 為什麼項目都採用預置體+UIView組件綁定方式？**
    - 1，統一化管理，工廠式創建，方便實現統一的動畫效果，一個公司的界麵顯示動畫，可能大多數情況下是統一風格，如果我們要實現統一定製化
    動畫，隻需要在UIView中統一處理，直接顯示通過UIManager.open()方式調用
    * 2，把記憶體及資源的管理交到管理器處理，減少開發者對何時釋放資源，何時加載資源的煩惱，隻關註自己的
    業務邏輯處理，無須關註資源的加載與釋放
    * 3，接口統一，方便後期對界麵的打開次數統計，以提供數據給營運人員，檢視該模塊的受歡迎程度
- **Q : 項目主要核心模塊為什麼都在管理器Manager上？**
    - 提高可讀性，新手上手快，拿到代碼隻能從Manager上直接了解整個項目的結構模塊，盡量避免全局變數滿天飛的情況
    後麵框架的使用者也可直接把全局的通過數據直接掛載到Manager中使用，減少全局變數的汙染。
- **Q : 項目為什麼推薦萬事盡量保留類型？***
    - 個人觀點，項目採用VSCode + Creator + typescript 方式進行開發，而typescript VSCode 都是Microsoft 公司
    的産品，Microsoft公司在JavaScript 基礎上加上了type,就是為了解決弱語言類型無類型化，可讀性差，
    * 1，您可以清楚你的實際來自哪一個類型，跟繼承的關係
    * 2，編輯友好加上VSCode的智能代碼提示跟靜態文法檢查，讓你在開發時，減少錯誤
    * 3，代碼更嚴謹，可在傳入參數中限製傳入的類型，類型的檢查交給VSCode處理
    * 4，方便重構，如果當你發現某個文件放置位置不對，可直接在VSCode中拖動到你想要的位置，VSCode會自動的更正你托動
    代碼所有引用的位置，或者對API 類名等修改操作，VSCode也會自動更改所有引用此類型的地方，降低重構的成本
    * 5，最後說一句，冇有人比VSCode 更懂TypeScript ,TypeScript的重點在Type,無論什麼情況，盡量保留類型。
# 框架定位
本框架主要為輕量級遊戲打造的一個基礎框架雛形，可適用於休閒類，小遊戲類，棋牌類，文字遊戲類等輕或中度型遊戲的開發，
功能還在完善中，後麵優化及功能的擴展繼續進行中
